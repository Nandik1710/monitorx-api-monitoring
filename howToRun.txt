7. Check light/dark, keyboard Tab, browser Back/Forward and direct URL reload at 1024px or wider. Check a

Manual browser verification (Chrome on localhost)
--------------------------------------------------
1. Open http://localhost:5173 and choose Create account. Enter a test email/name and a 12-128 character password.
2. Open http://localhost:8025, open that address's verification email, follow its link and press Verify email.
3. Sign in on the web page. The page should show your name with Renew session and Sign out controls.
4. Press Renew session once, then Sign out. You should return to the sign-in form.
5. Choose Request password reset, enter the same email, and open the reset message in Mailpit. Follow its link,
   set a new password and sign in again. The old password and consumed link must no longer work.
6. Optionally inspect cookie flags in browser developer tools: Secure, HttpOnly, SameSite=Lax, Path=/, no Domain.
   Never copy token values into issues, chat, logs or screenshots. No auth tokens are stored in localStorage.

Always use localhost for this HTTP development setup, not a LAN address. Browser Secure-cookie exceptions are
localhost-specific; use HTTPS for any non-localhost deployment. Production mode rejects HTTP origins. Frontend
and API must be same-site for SameSite=Lax sessions. APP_BASE_URL must match the browser origin exactly.

API endpoints: /api/v1/auth/{csrf,config,register,login,me,refresh,logout,resend-verification,forgot-password,
verify-email,reset-password,github,github/callback}. See docs/architecture/authentication.md for methods/contracts.
JSON mutations require Origin: http://localhost:5173, X-CSRF-Token from GET /csrf, and the matching cookie jar.
Use browser forms for local manual checks; do not paste session or email-token values into shell history.

Use a GitHub account with a verified primary email. An existing password account with the same email is deliberately
not auto-linked; use password login for that account. The default disabled setting needs no GitHub credentials.

Security defaults and limitations
---------------------------------
- Access sessions last 15 minutes; rotating refresh families expire absolutely after 7 days. Clients must serialize
  refreshes across tabs; replay/lost-response retries invalidate the family and require sign-in again.
- Verification links last 24 hours, reset links 30 minutes, OAuth state 10 minutes. Resends invalidate older links.
- Failed logins back off from 60 seconds after 5 failures, doubling to a 1-hour cap. API quotas are documented in
  docs/architecture/authentication.md; wait for their window if manual tests trigger 429 responses.
- Each scrypt operation needs about 128 MiB; size API memory and upstream concurrency limits before production.
- Historical Prompt 3 boundary: organization authorization was added in Prompt 4 below.
- Auth emails are sent synchronously. Failed delivery is audited; resend when SMTP is restored. Durable mail retry
  and automatic expired-record cleanup are not part of this phase.
- trust proxy remains false. Deliberately configure trusted proxy addresses at deployment; never trust arbitrary
  forwarded headers. Existing health endpoints remain process health, not a full auth-dependency readiness probe.
- Real GitHub-provider sign-in requires your optional credentials; local tests use controlled provider responses.
- howToRun.txt and updates.txt are currently ignored by your existing .gitignore. Their local edits are preserved;
  review that ignore policy yourself if you want these living documents included in version control.

Rotation and deployment notes
------------------------------
- secrets:init does not rotate keys. Privately add a new random key/version to TENANT_ENCRYPTION_KEYS, retain
  all old keys, select the new TENANT_ENCRYPTION_KEY_VERSION and restart the API. Use each secret's Rotate
  action; new writes automatically use the selected version. Retain old keys until live data and retained
  backups no longer require them. Never change a key's bytes under an existing version.
- KMS is an injectable provider interface only. The shipped entrypoint has no AWS adapter: setting
  TENANT_KEY_PROVIDER=kms with KMS_KEY_ID intentionally fails closed until an adapter is wired for deployment.
- The basic settings UI shows up to 100 entries; API lists support page/limit. Organization rename is API-only.
- Invitation SMTP is synchronous; failed delivery is audited and that token revoked. Resend after SMTP recovery.
  Automatic retry, expired-record cleanup, bulk rotation and an audit viewer are not implemented in this phase.
- See docs/architecture/workspaces.md for endpoint contracts, role matrix, crypto format and authorization.
