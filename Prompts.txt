MONITOR-X: ORDERED 15-PROMPT BUILD PLAN
=======================================

How to use this file
--------------------
Use exactly one prompt at a time, in order. Paste Prompt 1 into Codex first, then wait for the implementation and report. Do not ask Codex to execute later prompts early. Every prompt must inspect existing work, preserve working features, implement only its phase, run the relevant tests, update howToRun.txt and updates.txt, and clearly report what was done and what you must do manually.

Global rules for every prompt
-----------------------------
- Treat Supporting Documents/Monitor-X_Final_Production_Specification.pdf as the authoritative design.
- Work inside this repository and preserve existing user changes.
- Use TypeScript, strict validation, tenant-scoped authorization, safe defaults, and maintainable modules.
- Do not commit secrets or print secret values in logs, tests, output, or documentation.
- Do not claim a feature is complete without tests and a short manual verification path.
- Keep the API stateless; perform outbound monitored requests in workers.
- Keep PostgreSQL as the durable source of truth; Redis/BullMQ is reconstructible.
- Stop after the current phase. Do not begin the next prompt automatically.
